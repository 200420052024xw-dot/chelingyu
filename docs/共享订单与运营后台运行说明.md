# 共享订单与运营后台

本阶段把车凌驿小程序的订单、车辆开放时段和区域调度接入同一服务，并提供独立的 Web 运营后台。它对应[总体方案](./无人车共享运力平台升级改造总体方案.md)中的任务型配送和预约型运力使用。参考项目 `tangship` 只用于后台页面布局；车凌驿使用自己的社会化车辆、取货区归属、跨区只读、平台调度和车主开放时段规则。

## 本地启动

1. 执行 `npm install`、`npm run build:miniprogram`、`npm run build:admin`。
2. 设置服务端环境变量：
   - `SESSION_SECRET`：至少 32 字符，部署后保持不变；更换后现有登录会失效。
   - `ADMIN_BOOTSTRAP_PASSWORD`：至少 12 字符，首次建库时用于 `admin` 总部账号。
   - `DATABASE_URL`：PostgreSQL 连接串。省略时仅使用进程内数据，重启即清空。
   - `WECHAT_APP_ID`、`WECHAT_APP_SECRET`：启用小程序正式微信登录。
   - `ALLOW_DEMO_AUTH=true`：仅在 `NODE_ENV` 不是 `production` 时开放演示登录与区域演示账号。
   - `PORT`：默认 `3000`。
   - `ADMIN_UPLOAD_DIR`：车型与车辆照片的本地持久目录；不设置时使用 `server/uploads`。部署时应挂载持久磁盘。
3. 执行 `npm run start:server`，访问 `http://localhost:3000/admin/`。开发后台可另执行 `npm run dev:admin`，访问 `http://localhost:5173/admin/`。
4. 在 `miniprogram/.env` 中填写 `ORDER_API_BASE_URL`（服务端域名，不含 `/api`）与 `ORDER_DEMO_AUTH=false`，再次执行 `npm run build:miniprogram`。微信开发者工具可用电脑可访问的测试域名；真机需要 HTTPS 和小程序 request 合法域名。

生产环境设置 `NODE_ENV=production`，使用持久化 `DATABASE_URL`，并配置微信登录。首次登录总部账号 `admin` 后，在“运营账号”创建省级账号，由各级继续创建直属下级账号。已有数据库不会因重启而重置密码或业务数据。演示环境可设置 `ALLOW_DEMO_AUTH=true` 使用样例客户和各级运营账号；请勿把该开关用于生产。

运营账号现在逐级创建：平台创建省级，省级创建直属市级，市级创建直属区级。平台为价格项设全国范围，省市逐级收窄，区级设执行价。初始价格仍为基础费 5 元、每公里 2 元、冷链 1 元；需要先由上级放宽范围，下级才能调整。上级收窄后若下级规则越界，该区域暂停新报价，历史订单金额不变。

车主可在“名下车辆”提交车辆编号、车型、运营区域及照片；所属区审核后，车主还需开启共享和开放时段才会进入可调度车池。管理员车辆点位与小程序距离在当前阶段基于演示位置。平台可在“车型照片”上传单张 PNG、JPEG 或 WebP（不超过 5MB）；小程序共享模式会读取更新后的照片。正式部署须为上传目录提供持久存储及小程序可访问的 HTTPS 图片域名。

## Coze Coding 部署

后台静态文件和 API 放在同一个 Coze Coding 项目，构建命令为 `npm install && npm run build:admin`，启动命令为 `npm run start:server`。在项目环境变量配置上述服务端密钥和 Coze PostgreSQL 的 `DATABASE_URL`，通过 `/api/health` 检查服务，再把其 HTTPS 域名配置到小程序 `ORDER_API_BASE_URL` 及微信小程序 request 合法域名。两个独立 Coze 项目的数据库不共享，所以小程序只调用此项目的 API。

## 已实现流程

- 用户选地址、货物、车型和时段后创建订单；服务端核对报价与草稿，模拟支付成功后处理派车。未配置 `ORDER_API_BASE_URL` 时仍使用原有本地演示流程，设备上的旧演示订单不会自动上传。
- 即时附近车辆订单自动按车型、载重、开放时段、电量与预约冲突匹配。预约或需要平台调度的订单先由取货区审核；更换车型时客户需确认新报价，然后支付、派车。
- 取货区处理订单；目的地区对同城跨区订单只读。上级运营可介入，必须填写原因。客户确认装货与收货，取消或异常结束时释放车辆占用并记录模拟退款。
- 后台提供工作台、订单筛选与详情、通知、区域运力、总部账号配置。车主可在小程序维护共享和开放时段。订单详情的路线与位置是模拟展示，不代表真实车载定位。

## 当前边界

支付、退款、车辆位置、车辆绑定均为模拟；真实微信支付、车载设备接入、实名车主审核、结算分润和运价分级审批尚未接入。PostgreSQL 当前采用一行 JSONB 加事务行锁保存共享状态，能保证本阶段订单与车辆预约原子更新；面向大规模区域运营时应迁移为独立订单、车辆、预约和账务表。服务区域和样例车辆目前在 `server/state.ts` 初始化，新增城市需要扩展区域、车辆及管理能力。
