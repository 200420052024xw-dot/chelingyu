# 实施顺序与验收

## 分阶段交付

| 阶段 | 实现内容 | 验收出口 |
|---|---|---|
| 1. 修订数据 | 根据 04-rules 对齐类型、DTO、场景种子 | 引用完整、时间线与状态一致；编译校验通过 |
| 2. 工程骨架 | 原生工程、三 Tab、主题、通用组件、服务注入和存储 | 开发者工具可运行；重启可恢复本地数据 |
| 3. 下单链路 | 地图、地址、货物、车型、报价和待支付订单 | 完整走通图 001～005；修改上游数据使旧报价失效 |
| 4. 履约链路 | 支付模拟、调度、详情、状态时间线、取消退款 | 一笔订单能完成，也能取消并展示退款 |
| 5. 车主管理 | 车辆、绑定演示、开放时间、任务和收益 | 改共享时段影响后续调度，完成任务生成一次收益 |
| 6. 补齐体验 | 预约、消息、客服、失败与空状态 | 多种场景可重置演示；预约按演示时钟推进 |
| 7. 真机验收 | 布局、返回导航、地图、权限拒绝和前后台切换 | 核心链路在微信真机可演示，明确模拟边界 |

## 必要验证

使用纯函数测试覆盖计价与分润取整、跨午夜时段、订单允许迁移和预约冲突；用服务集成测试覆盖跨实体一致性。无需为静态文案或简单样式堆积测试。

关键场景：

1. 连点下单仅生成一单；连点模拟支付不重复扣款/写支付成功记录。
2. 报价过期和修改草稿后旧报价均不能被接受。
3. 两笔订单竞争同一辆车，仅一笔成功占用，另一笔获得明确结果。
4. 无车、授权窗口不足、电量不足、位置缺失时不能派车。
5. 支付成功但匹配失败，会创建退款；重复退款完成事件不重复记账。
6. 取消前往取件订单后资源释放；执行中的订单不能直接跳取消并释放车辆。
7. 重复确认收货仅生成一组分润；总分润严格等于可分配金额。
8. 车主看不到他人车辆与收益；切换演示身份不残留上一用户草稿。
9. 修改/删除常用地址后，历史订单的地址保持原样。
10. 退出重进仍保留订单；存储失败不会显示提交成功。
11. 预约占用不与其他订单时间重叠；修改共享时段不得破坏已承诺预约。
12. 手机拒绝定位、地图加载失败、无订单和无车辆时有可操作回退。
