## 本阶段决策

| 项目 | 决策 |
|---|---|
| 客户端 | 原生微信小程序，TypeScript、WXML、WXSS |
| 页面 | 首页、订单、我的三个底部入口；车主功能从“我的车辆”进入 |
| 组件 | 自建业务组件；通用表单、弹窗可采用 TDesign，具体版本在工程创建时验证并锁定 |
| 运行 | 一个小程序，使用本地模拟服务和本地存储 |
| 地图 | 原生地图展示；演示点位、路线、到达时间由地图适配器提供 |
| 数据 | 沿用 `data_design/types.ts`，运行前处理本设计列出的数据修订 |
| 后端 | 预留异步服务接口，接入真实后端时替换适配器 |
| 管理后台 | 独立产品边界，本期不创建管理端页面 |
| 并发架构 | 当前无需消息队列、微服务、缓存集群或独立调度集群 |

## 首版范围

实现普通用户的地址管理、即时配送、单次预约配送、报价、模拟支付、匹配、履约、取消退款、历史订单，以及车主的车辆绑定演示、车辆查看、开放时段和收益查看。消息中心与客服工单提供最小可用流程。

企业周期包车、真实车辆通信、真实支付结算和省市区后台属于后续阶段。系统保留其模块归属，不把未实现功能显示为可用服务。

模拟运行是单设备、单本地数据集的体验，不能实现真实跨用户接单、设备通信或资金交易。角色切换仅供演示。

## 产品假设

- 选车型是用户提出能力偏好，系统最终分配具体车辆。点击地图车辆可查看详情，不承诺锁定该车。
- 下单页“预约用车”指一次配送的预约取件时间，不代表企业包时段运力。
- 首版要求用户自行装卸；原图“需要搬运”开启后提示当前不支持，并阻止下单。
- 运营商、车主均不能绕过平台直接报价和收款。
- 首版模拟支付成功后匹配车辆；无车或调度失败进入取消及模拟退款流程。

这些假设作为实施默认值；产品规则变化时同步更新本目录与数据契约。
